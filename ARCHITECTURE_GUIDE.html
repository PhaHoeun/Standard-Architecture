2. The Complete Dependency Chain: Who Uses What?

In Riverpod Clean Architecture, components connect through a clear, predictable chain of injections. Here is the exact path:

Step 1: dioProvider ➔ used in PostRemoteDataSource Infrastructure Level
Defined in: lib/core/network/dio_provider.dart
Consumed in: lib/features/posts/data/datasources/post_remote_data_source.dart 
@riverpod
PostRemoteDataSource postRemoteDataSource(Ref ref) {
  final dio = ref.watch(dioProvider); // 🔗 INJECTION: Reads shared Dio instance
  return PostRemoteDataSource(dio: dio);
}
▼
Step 2: postRemoteDataSourceProvider ➔ used in PostRepositoryImpl Data Layer
Defined in: lib/features/posts/data/datasources/post_remote_data_source.dart
Consumed in: lib/features/posts/data/repositories/post_repository_impl.dart 
@riverpod
PostRepository postRepository(Ref ref) {
  final remoteDataSource = ref.watch(postRemoteDataSourceProvider); // 🔗 INJECTION
  return PostRepositoryImpl(remoteDataSource: remoteDataSource);
}
▼
Step 3: postRepositoryProvider ➔ used in PostsController Controller Level
Defined in: lib/features/posts/data/repositories/post_repository_impl.dart
Consumed in: lib/features/posts/presentation/controllers/posts_controller.dart 
@riverpod
class PostsController extends _$PostsController {
  @override
  FutureOr<List<Post>> build() async {
    final repository = ref.watch(postRepositoryProvider); // 🔗 INJECTION
    return repository.getPosts(); // Returns pure domain entities!
  }
}
Step 4: postsControllerProvider ➔ used in PostsScreen (Widget) Presentation Level
Defined in: lib/features/posts/presentation/controllers/posts_controller.dart
Consumed in: lib/features/posts/presentation/screens/posts_screen.dart 
class PostsScreen extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // 🔗 OBSERVATION: Watches controller and rebuilds when state changes
    final postsAsync = ref.watch(postsControllerProvider);

    return postsAsync.when(
      data: (posts) => ListView.builder(itemCount: posts.length, ...),
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (err, stack) => Text('Error: $err'),
    );
  }
}
▼
Step 5: PostsScreen ➔ registered in app_router.dart Navigation Level
Defined in: lib/features/posts/presentation/screens/posts_screen.dart
Consumed in: lib/core/router/app_router.dart 
@riverpod
GoRouter goRouter(Ref ref) {
  return GoRouter(
    routes: [
      GoRoute(path: '/', builder: (context, state) => const PostsScreen()), // 🔗 ROUTE
      GoRoute(path: 'posts/:id', builder: (context, state) => PostDetailScreen(...)),
    ],
  );
}
▼
Step 6: goRouterProvider ➔ consumed in App (Root) App Root
Defined in: lib/core/router/app_router.dart
Consumed in: lib/app.dart 
class App extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final router = ref.watch(goRouterProvider); // 🔗 INJECTION: Supplies router to MaterialApp
    return MaterialApp.router(routerConfig: router, theme: AppTheme.lightTheme);
  }
}

4. Data Transformation Chain: From JSON to Pixels

Layer Data Shape & Code Why It Changes Here
1. Backend API {"id": 1, "userId": 1, "title": "..."} Raw network JSON string over HTTP.
2. Data Source PostModel.fromJson(json) (Freezed DTO) Deserializes JSON with safe fallbacks (@Default('')) and null-safety.
3. Repository model.toEntity() ➔ Post (Domain) Converts DTO into clean, immutable business entity. Shields UI from API changes.
4. Controller AsyncData<List<Post>> Riverpod wraps data in loading/error/data states for the UI.
5. Widget / Screen Text(post.title) Rendered onto the screen inside Material widgets.

6. Recipe: How to Build Any New Feature

The 5-Step Formula for New Features (e.g. features/notifications/):

1. Domain: Define NotificationItem entity and abstract NotificationRepository.
2. Data: Create NotificationModel (Freezed), NotificationRemoteDataSource (Dio), and NotificationRepositoryImpl.
3. Controller: Create NotificationsController with @riverpod.
4. Presentation: Build NotificationsScreen (ConsumerWidget) and add route to app_router.dart.
5. Code Gen: Run dart run build_runner build.
